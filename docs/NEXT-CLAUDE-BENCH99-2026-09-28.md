## 2. 지표별 공격 계획 (우선순위 순, 각 항목 = 가설 → 첫 실험 → 성공 기준)

### A. PDF 글 order 0.982 → 0.99 (손실 5.4만 자, 상위: kats 1.2만·시험지 4종 1.3만·편람 4,180·80168 2,244·pii 2,145)

0. **[착수됨 — 검증 먼저] 미주 재배치 `src/pdf/endnotes.ts`**(커밋 `다음 커밋`): 문서 끝 미주 묶음을 참조 블록(표 칸 글 포함, 앞쪽 유일) 뒤로 옮긴다. 가장 흔한 머리 꼴("문#）")만, 짝 3개 이상·본문 순서. 실측: 시험지 3-11월 order 0.497→0.597, 3-09월 0.579→0.752. **전체 게이트·PDF 글/표 정답 전체·ODL per-doc 는 아직 안 돌렸다 — 다음 세션 첫 작업으로 돌려 회귀 0 확인**(회귀 있으면 조건을 좁히거나 되돌림). 남은 문제: 선택과목별로 되풀이되는 23~30번은 "앞쪽 유일" 조건에서 빠져 여전히 끝에 남는다 → 해설 머리의 과목 표지("22_11_실전 23) [확률과통계]" 등)로 구간을 나눠 과목별로 짝짓기. 본문 문제들은 쪽 틀 표 한 칸 안에 2단이 섞여 있어(문6·문1 한 칸) 순서 손실의 나머지는 그 틀 표 안 2단 읽기다.
1. **각주를 참조 자리로 옮기기 (가장 큰 단일 레버)**. HWPX·HWP5 파서는 각주를 본문 참조 자리에 `(주: …)`로 끼워 낸다(`src/hwpx/notes.ts`). PDF 는 쪽 아래에 따로 낸다 → 시험지 해설·보고서 각주가 통째로 순서·어절을 깎는다. PDF 에서 각주를 복원하라:
   - 쪽 아래 띠의 작은 글자 블록 중 머리가 참조 번호(`1)`, `주1`, 위첨자 숫자, `*`)인 것 = 각주 본문.
   - 본문에서 같은 번호의 위첨자(작은 글자·기준선 위)를 찾아 그 문단 끝(또는 참조 직후)에 `(주: …)` 로 삽입. HWPX 출력과 **포맷 간 일관성**이라는 실제 가치가 있다.
   - 첫 실험: `rhwp/3-11월_실전_통합_2022`(order 0.50)·`task1725`·`SO-SUEOP` 에서 각주 블록 검출 정확도 출력. 성공: 시험지 order 0.9+, 전체 order +0.004 이상, ODL 무회귀(ODL 정답도 각주를 본문 끝이 아니라 쪽 아래에 두는지 먼저 확인 — 다르면 `footnotesInline` 을 PDF 기본으로 하되 ODL 경로 영향 per-doc 확인).
2. **그림·개념도 속 글상자 순서**(kats 개념도, `lo-pairs`): DOCX 정답은 그리기 개체 순서. PDF 에서 한 그림 영역(image/벡터 그룹 bbox) 안 글은 위→아래·왼→오른 행 우선으로 묶어 그림 단위로 연속 출력하는지 확인. 지금은 본문 XY-Cut 에 섞여 흩어진다.
3. 편람·규제분석서: `bench/.order-dbg.mjs`(이번 세션에 만든 LIS 밖 유닛 구간 출력기 — scratch 에서 다시 만들 것) 로 뒤바뀐 구간을 유형별로 세고 상위 유형부터.

### B. PDF 글 precision 0.987 → 0.99 (가짜 글 3.56만 자, 필요 −7천)

1. **목차 점 리더**: 빼면 +0.0039(이번 세션 실측)인데 ODL 018·113·114 가 떨어졌다. 두 정답이 다른 이유를 먼저 확인: ODL 정답이 점을 담는 문서는 **점이 실제 글자(마침표 글리프)로 찍힌 목차**, HWPX·DOCX 정답에 점이 없는 문서는 **탭 채움 리더**다. PDF 에서 구별하는 기하 신호를 찾아라:
   - 한컴·Word·LibreOffice 탭 리더는 점 사이 간격이 글꼴 전진폭과 다르게 **정확히 등간격**이고 쪽 번호 앞 오른끝 탭 정지점에서 끝난다. 사람이 친 점은 글꼴 전진폭 그대로.
   - 점 글리프가 한 showText 안에 연속으로 들어 있는지(사람이 친 것) vs 점마다 Tm 이동(리더) — 연산자 목록으로 판별.
   - 성공: pdf-text precision +0.003 이상 & ODL 018·113·114 무회귀.
2. **쪽 틀 표의 머리·꼬리 행**(SO-SUEOP "협성고등학교 | 쪽번호" 등): 이번 세션 시도는 통계표 반복 머리 행까지 지워 표 exact −1.6%p. 가를 신호:
   - 틀 표는 **모든(≥80%) 쪽**에 같은 위치·거의 같은 bbox 로 있고 본문 영역 전체를 감싼다(높이 ≥ 쪽 본문 60%). 쪽 넘김 통계표는 연속 쪽 일부에만, 머리 행 아래 데이터 행이 쪽마다 다르다.
   - 떼는 행은 **쪽 번호 숫자를 포함**하거나 쪽마다 글이 완전히 같은 1행뿐.
   - 성공: SO-SUEOP precision +0.05, 표 exact 94.39% 이상 유지.
3. 나머지 상위: 편람 7,513(쪽 반복 제목 행 — 원본 1회분은 남기고 반복분만), 156775717·156775878 통계표, hwp3-sample16, aift, nested_group_vectors(0.82). 각 문서의 precision miss 전체를 덤프해 유형별로 센다(`PTX_DUMP` 패치 방식: pdf-text-gt 의 coverage misses 를 파일로).

### D. 한국 PDF 표 exact 94.39% → 99% (오답 약 150표)

오답을 전수 분류해 유형별로 풀 것. 이번 세션 확인된 유형과 공략:
1. **보이지 않는 열**(연락처 표 "과 장 | 이름 | 전화", 42표 안팎): 선 없는 칸 안에서 **여러 행의 글 시작 x 가 같은 자리에 정렬**되면 그 x 를 열 경계로 추가. 이름+전화가 한 아이템이면 글리프 흐름(연산자 목록)의 위치로 쪼갠다(`tracked-text.ts` 가 쓰는 글리프 흐름 맞춤을 재사용).
2. **표 안 단위 행** "(단위: …)"(가계동향·벼고추 등 39표): 원본이 표 첫 행인지 표 앞 문단인지 기하로 가를 신호를 찾는다 — 단위 줄이 표 오른끝에 정렬·표 윗변과 간격 < 한 줄·같은 글꼴 크기 → 첫 행. 91곳 표 앞 문단과 39곳 표 첫 행을 가르는 결정 트리를 코퍼스에서 학습(규칙 2~3개)하고 두 쪽 모두 정확도 95%+ 일 때만.
3. **셀 간격 상자 여럿 = 한 표**(156775997 지게차 8×4): 폭이 같고 세로로 쌓인 상자 사이 틈이 좁으면(≤ 상자 안 줄 간격) 한 표의 행들로 합친다.
4. 가계동향 35표·편람 2쪽 모아찍기·issue3637 cairo: 개별 원인 문서화돼 있음(`docs/nested-tables-forms-session-2026-09-27.md`).
5. 채점기 정합(명시 필요): 칸 글의 숫자 천 단위 구분·전각/반각 괄호 등 표기 차이만 다른 칸을 같은 칸으로 볼지.

### E. ODL 기본 0.937 → 0.99 / 최고 설정 0.971 → 0.99

1. **OCR 품질**(남은 손실 최대): 그림 속 저해상도 영문 차트("Televislon"). 가설 순서:
   - 영문·라틴 인식 모델 추가(PP-OCRv5 en/latin rec, 모델 스펙은 `src/ocr/models.ts` 형식으로 SHA 고정, `kordoc models` 번들 포함): 글줄마다 한국어·라틴 두 모델 결과 중 CTC 신뢰도 높은 쪽.
   - 영역 다시 읽기 배율을 글자 높이 기반으로(검출 상자 높이 < 32px 인 영역만 ×3~×4). 전체 ×6 은 들쭉날쭉이었다.
2. **차트 제목·범례 = 정답의 제목(#)·"■ 범례"**: ODL 148·147·150 은 정답이 차트 제목을 `#` 로 둔다. OCR 영역 글 중 가장 큰 글자 한 줄이 영역 위쪽에 있으면 제목 후보로.
3. 기본 설정: 그림 자리 표시가 −0.006. 이미지 바이트를 저장하지 않는 호출(`images: false` 가 아닐 때도 CLI stdout 등)에서 자리표시가 가리킬 파일이 없으면 기본으로 빼는 것을 검토(유저 결정 필요 — 이번 세션 정책은 유지였음).
4. 표 HTML: `htmlTables` 를 켜면 +0.004. 기본값 전환은 유저 결정.

### F. OCR 정확도 → 0.99

1. 정답(같은 PDF 텍스트층 파싱) 결함부터 고친다 — 지난번 CER 잔여의 83% 가 정답 결함이었다. `bench/ocr-accuracy.mjs --dump=dir` 로 문서별 GT/OCR 를 떠서 오차 상위 문서의 GT 쪽 결함(텍스트층 파서 버그)을 먼저 잡으면 PDF 글 정답도 같이 오른다.
2. 인식: 저신뢰 줄만 두 배 재인식은 이번에 오히려 나빠졌다(축소 래스터 탓 −, 재인식 탓 −). 대신 (a) 한 번에 ×4 로 그려 줄 높이 정규화, (b) 한국어 사전 기반 CTC 빔서치(형태 사전 or 문서 어휘 WrapLexicon), (c) 검출 상자 여백 보정.
