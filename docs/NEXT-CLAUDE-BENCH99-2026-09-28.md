## 1. 작업 규칙 (실측으로 얻은 함정)

- 빌드 후 벤치: `npm run build` → 벤치. **게이트·벤치가 도는 동안 재빌드 금지**, 게이트 중엔 무거운 작업 금지(fuzz 느림 판정 플레이크).
- 네 벤치를 한 묶음으로 본다. 이번 세션 러너(스크래치, 다시 만들 것):
  - `four.sh <kordoc 루트> <태그>` — 글·표(--no-ocr)·ODL 기본 병렬 → OCR·ODL best 병렬, 결과 json 을 `res/<태그>/` 에 모음. ODL 은
    `odl-run.mjs <루트> <out> '<opts JSON>'` 로 예측을 만들고 `$ODL/.venv/bin/python $ODL/src/evaluator.py --prediction-root <out>/prediction --engine kordoc`.
  - `cmp4.py <resA> <resB>` — 네 벤치 요약 + 문서별 DOWN/UP. **기준선은 git worktree 로 옛 커밋을 따로 빌드**해 같은 채점기로 돌린다
    (채점기를 바꿨으면 기준선도 새 채점기로 다시).
  - src 로 바로 재는 사본: `sed 's|"../dist/index.js"|"../src/index.ts"|; s|"pdf-text.json"|"_src-pdf-text.json"|' bench/pdf-text-gt.mjs > bench/_src-...` 를
    tsx 로(출력 파일 이름을 바꿔 도는 벤치와 안 겹치게). 디버그 패치: ODBG(LIS 밖 유닛 구간), PDUMP(precision 미스), WDUMP(어절 차이).
- zsh: `echo ===` 는 `=cmd` 확장으로 실패, `$var` 는 단어 분할 안 됨(`env $e` 로 두 변수 못 넘김).
- npm·npx 는 `/opt/homebrew/bin/npm`. git push 는 `git -c url."ssh://git@ssh.github.com:443/".insteadOf="git@github.com:" push`. main 직접 커밋.

## 2. 남은 지표별 공격 계획 (각 항목 = 가설 → 첫 실험 → 성공 기준)

### A. PDF 글 order — 달성(0.99094). 여유를 늘리려면

1. 시험지 4종(order 0.80~0.89): 해설 쪽 머리가 본문 줄에 섞여 미주 머리 몇 개(4·5·6·30번)가 짝을 못 찾는다. ODBG 로 남은 구간을 보고 해설 쪽 2단 읽기부터.
2. kats 약어 표(x14 유닛): DOCX 표 칸 순서와 PDF 칸 순서 차 — 표 행 우선 읽기 확인.
3. hwp3-sample11·16: 흩어진 한 유닛 어긋남 — 유형별로 세어 상위부터.

### B. PDF 글 spaceF1 0.98436 → 0.99 (오차 토큰 약 36% 줄여야)

오차 토큰(2만4천) 분해(WDUMP 전수): 줄 꺾임 이음에서 띄운 쪼갬 2,968쌍(≈8.9k 토큰)·붙임 1,017쌍(≈3k)·나머지(문장부호 붙음·숫자·라틴).
쪼갬의 대부분은 line-wrap 이 "근거 없으면 띄움"(원문 붙음 18%)으로 둔 자리다 — 새 신호가 필요하다. 후보:
- 문단별 줄나눔 모드(글자/어절) 추정: 문서·문단 안에서 증거로 확정된 꺾임이 모두 어절 경계면 어절 모드(→ 띄움), 어절 중간 꺾임이 있으면 글자 모드 —
  글자 모드 문단의 "근거 없음" 자리 붙음 비율을 코퍼스로 재 보고 50% 넘으면 기본값을 뒤집는다.
- DOCX 순서 목록 번호: kordoc DOCX 파서가 번호 목록을 모두 "1." 로 내 정답에 "1." 토큰이 남는다(kats 82·kpipa 55) — 실제 번호(lvlText) 복원.

### C. 한국 PDF 표 exact 94.39% → 99% (오답 151, 가계동향 다른 판 35 포함)

오답 유형(이번 세션 전수): 매칭 실패 44·행 부족 31·행 과다 20·열 부족 14·행열 모두 부족 14·크기 같고 병합 다름 11 ….
1. 가계동향(156775700)은 PDF 가 HWPX 와 다른 판(글 3배, 행이 더 있음) — 글 벤치처럼 "정답지 부족" 모수 제외를 표 벤치에도 적용할지 결정(채점 기준 변경).
2. 보도자료 연락처 표 2×6 → 2×4(8표 안팎): 한컴 구버전(1.3.0.524) PDF 는 칸 클립이 없고 "부장 | 김완석 | (전화)" 사이 세로선이 없다 — 두 행 글 시작 x 정렬로 열 경계 추가.
3. 쪽 넘김으로 두 조각 난 표(156775838 8×2 → 4×2 둘): 같은 모양 별개 표 두 개와 가르는 신호(쪽 끝·쪽 머리 위치, 폭·열 경계 동일) 찾기.
4. 벼고추 단위 행·편람 모아찍기 중첩표 등은 `docs/nested-tables-forms-session-2026-09-27.md`.

### D. ODL 기본 0.937 / 최고 0.973 → 0.99

- 기본 설정 손실의 큰 몫은 스캔 문서(141·110·148 — OCR 없이는 글이 없음). OCR 기본값·그림 자리표시·htmlTables 기본값은 **유저 결정**.
- best: 148(차트 제목을 정답이 `#` 로 — OCR 줄 크기 차 1.14배뿐이라 보류), 141, 098(지도 OCR), 106, 027.

### E. OCR 정확도 → 0.99

오차 유형(dump 분석): ① 정답 결함 — 그림 속 글(인포그래픽·로고)을 OCR 은 읽는데 텍스트층 정답엔 없음(web045 +270자·kmcc 로고) → OCR 쪽 출력에서
그림 영역(텍스트층 없는 이미지) 글을 빼고 재는 채점 변경 검토. ② 법령 괄호 ｢｣ 를 OCR 이 [ ] 로 읽음 → 후처리. ③ 인식 누락(web068). CER 은 예산서
순서 차가 크다(글자 P/R 0.996 인데 CER 0.18~0.27).
